# Kairos

个人工作与生活助手，也是一个从零学习 agent 开发的项目。

Kairos 是希腊语里“恰当的时机”。这个助手和普通聊天机器人最大的区别，是会在对的时候主动找你：早报、到点提醒、每周回顾。

核心部分（agent 循环、模型适配层、记忆）都是手写的，不依赖 agent 框架。学习计划见 [本地 14 周计划](docs/个人%20Agent%20助手%2014%20周计划.html)，实验记录见 [docs/learning-log.md](docs/learning-log.md)。

源码参考范围见 [本地项目参考清单](references/SOURCE-MANIFEST.md)。用户无特殊说明时，只参考该清单内的本地项目，不额外补充其他项目。

会话系统第一版已实现本地保存、恢复和切换；通用对象、ID 生成方、关联关系及代码接口见 [会话系统设计](docs/会话系统设计.md)。

记忆系统第一期已实现：全局核心记忆、每轮后台提取、程序生成索引及按需读取。使用规则、工具接口、四张流程图和下一期事项见 [记忆系统设计](docs/记忆系统设计.md)。

只看函数作用、调用位置和改动前后关系，可阅读 [会话系统代码框架与改动对照](docs/会话系统代码框架与改动对照.md)。

同一代码范围的分层索引、模块调用图与展示方式比较，见 [代码阅读六种视图](docs/代码阅读六种视图/README.md)。

当前项目已完成阶段 0 的多轮对话和 token/费用统计，以及阶段 1 的 s1-1 至 s1-9，并支持图片输入和持久化多会话。主程序通过 `kairos.runtime.AgentRuntime` 使用 Agent loop；`terminal_input.py` 管理终端图文草稿，`cli.py` 负责命令与提交，`terminal_renderer.py` 负责 Rich 渲染。s1-10 的双模型对比和阶段 2 仍待完成。接手时先读 [HANDOFF.md](HANDOFF.md) 和 [CLAUDE.md](CLAUDE.md)。

## 当前架构

主程序只有一个对话入口，组件由统一运行时组装：

```text
kairos 主入口
  -> cli.run()                  CLI：输入、斜杠命令、展示
  -> AgentRuntime.respond()    会话、模型、工具、数据库和日志的协调
  -> run_agent_turn()           模型请求、工具执行和跨轮循环
  -> providers/                 OpenAI 兼容或 Anthropic Messages 适配器
  -> sessions.py + SQLite       会话、回合、步骤、消息和工具调用记录
  -> todos.py + SQLite          待办工具和持久化数据
```

`src/kairos/runtime.py` 是应用的组装和协调边界：它根据 `Settings` 创建模型适配器，初始化 SQLite、会话存储和待办工具注册表，加载当前会话的模型上下文，并把一次用户输入交给 Agent loop。`sessions.py` 持久保存完整消息及 ID 关联，`execution.py` 在模型和工具的执行边界记录步骤。`src/kairos/cli.py` 只负责终端输入和命令，`src/kairos/terminal_renderer.py` 负责把结构化结果渲染为终端内容。

交互输入由 `terminal_input.py` 的 prompt_toolkit 编辑器负责；提交后交给现有 Rich 流式输出。`clipboard.py` 封装 macOS 原生剪贴板读取，`images.py` 负责图片校验、处理、快照和摘要。普通管道和功能受限的终端保留文字输入。

协议实现位于 `src/kairos/providers/`：`OpenAICompatibleModel`、`AnthropicMessagesModel` 和共享的响应转换逻辑分别放在独立模块中。主程序只通过 `runtime.create_runtime()` 创建运行时，不再保留一次性 Agent 包装入口。

### 上游 AI 网关

当前 Kairos 的上游接入用户自己的本地 AI 网关，调用链为：`Kairos → 本地 AI 网关 → 模型服务`。网关仅透传请求和响应，不做其他处理。模型协议适配、Agent 循环和工具执行由 Kairos 自身负责。

## 流式对话与工具调用

主 CLI 默认使用流式输出，OpenAI 兼容协议和 Anthropic Messages 均支持：

1. 正文片段收到就展示，同时累积完整模型响应；工具参数单独收集，不作为正文打印。
2. 本次模型响应正常结束且全部工具参数完整后，按返回顺序串行执行整批工具。
3. 把整批工具结果写入历史并交回模型，继续流式接收后续回答；没有工具调用时结束 Agent 回合。

终端使用 Rich 活动区域渲染 Markdown 和 Mermaid 代码面板；长回答生成时显示末尾，响应结束后保留全文。重定向到文件或管道时逐段输出原始正文，不写入终端重绘控制码。整轮结束只补充用量统计，不重复打印答案。“上下文窗口”单独一行，展示最后一次请求的完整输入量／窗口上限及占比，包含该次请求的全部历史，不含其随后新生成的输出，也不等于下一轮剩余预算。下一行集中展示当前会话的累计输入、缓存命中、输出、思考明细与费用；新建会话归零，恢复旧会话从数据库继续累计，启动和切换时立即显示。API 未返回的用量明细显示“未知”；只累计有效费用快照，存在缺项时标明“部分未估算”，不将缺失数据当成免费。单轮用量和每次请求的费用快照保存在同一会话数据库中，旧记录按原请求时间和升级时的本地价格表一次性补估；自然语言按需查询尚未接入。存储口径和查询方案见[会话用量统计](docs/会话用量统计.md)。思考内容保留在模型历史中，不混入正文；Anthropic 内容块顺序和思考签名保留用于后续请求。

回复使用统一浅色样式：代码块和 Mermaid 面板为浅灰背景、柔和语法高亮，行内代码为无底色深青文字，标题左对齐加粗、取消紫色和下划线。代码块标注语言，段落保留清晰留白。静态回答、流式重绘与最终全文共用这套样式；输入提示符和附件底栏独立保持原样。

代码调用 `runtime.respond(prompt, on_event=handler)` 可接收 `text_delta`（`text`、`request_number`）及模型请求、响应、错误和工具结果事件。未传 `on_event` 时沿用完整响应接口；注入的模型只有 `complete()` 时会逐次展示完整模型响应。流式读取失败不会自动重跑整个回合。内置的 OpenAI／Anthropic 适配器在流式和非流式下使用相同的完整性检查：缺少结束标记、工具响应被截断或整批中任一工具参数不是完整 JSON 对象时，拒绝整次响应中的工具执行；纯文字的长度截断仍可展示并提示。

Ctrl+C 或断流时，未完成模型响应不写入历史；已执行工具及其结果保留，工具副作用不会自动撤销。工具批次中断时给剩余调用补齐未执行或结果未确认标记。JSONL 日志和最终结果仍记录完整模型响应与工具结果，不逐片段重复保存正文。

尚未产生完整助手消息就失败的用户输入会从后续模型上下文撤回，但仍以 `in_context=false` 保存在 SQLite 中供检查。恢复会话时只修补未完成的记录并提示中断，不自动重跑模型或工具。

## 快速开始

需要 [uv](https://docs.astral.sh/uv/)。

```bash
mkdir -p ~/.kairos
chmod 700 ~/.kairos
cp .env.example ~/.kairos/.env  # 然后编辑该文件，填写模型与网关配置
chmod 600 ~/.kairos/.env
uv run kairos
```

## 会话保存与恢复

```bash
uv run kairos                 # 新建会话
uv run kairos --continue      # 恢复最近的会话
uv run kairos --session ID    # 恢复指定会话，支持唯一 ID 前缀
```

`--continue` 与 `--session` 互斥；找不到可恢复会话时会提示错误并退出。进入 CLI 后使用 `/sessions` 查看短 ID、标题、更新时间和当前会话标记，再用 `/resume ID` 切换。默认标题取首条输入，可用 `/rename 标题` 修改。新建的空会话已经存入数据库，但只有发送过消息或手动命名后才进入列表。

退出程序不会删除会话；`/new`、`/reset` 和 `/system 文本` 都会开启新会话并保留旧会话。切换、新建成功后清理当前附件草稿，失败时保留草稿。恢复会话会加载原 system 提示词、provider、model、思考设置及图文历史；密钥和服务地址仍读取当前配置，不保存到会话。

`/history` 查看当前模型上下文；`/history --ids` 查看会话、回合、步骤、消息和工具调用的关联，包括已撤出上下文的输入记录。两种展示都只显示图片摘要，实际数据库保存处理后的图片快照，因此恢复后仍可追问原图。

第一版支持单进程串行使用，没有跨进程并发写入保护。已通过离线测试及真实 PTY 的退出恢复检查，真实模型环境下的会话体验仍待验收。

## 查阅历史会话

主模型可通过 `search_history` 查找过去的讨论，再通过 `read_session` 阅读命中消息所在的回合。例如可以直接问“之前为什么决定主题平铺”。已有来源 ID 时可直接读取，不必先搜索。

默认查询当前用户数据库中已结束回合的用户和助手正文；业务工具内容按需打开。搜索返回少量最佳结果，读取支持相邻回合和长正文续读。工具只提供经过图片与协议字段过滤的资料，不切换或重新执行旧会话。接口、范围和分页边界见 [历史会话查询工具](docs/历史会话查询.md)。

本功能与长期记忆相互独立：`read_memory` 查主题文件，`read_session` 查原始会话。此次没有调整现有后台提取和记忆写入逻辑。

## 全局记忆

所有会话共用当前用户 `~/.kairos/memory/`，不按项目隔离：

- `CORE.md` 保存用户明确要求记住的内容，以及后台自动提取的姓名／称呼、通用交流偏好和通用协作约定；`MEMORY.md` 是程序生成的完整主题索引。两者每次模型请求都会加载，原聊天历史不重复保存这些注入内容。
- `topics/` 平铺保存自动提取的主题，一个文件一个主题。模型按索引调用 `read_memory`，读出的正文作为正常工具结果留在当前会话；新会话不自动继承正文。
- 正常应用入口在每个完整用户回合结束后排队提取，使用独立模型上下文和客户端，前台回复不等待；后台可读取主题、追加核心或主题，不能执行待办。
- 默认 DeepSeek Chat Completions 后台提取启用 `response_format={"type":"json_object"}`，包括工具续轮，并保留原思考设置；前台聊天不启用此模式。结束状态仍由程序校验，不增加自动重试或从解释文字提取 JSON 的逻辑。自定义提取模型工厂自行管理输出参数。
- 自动核心记忆限于用户直接表达的姓名／称呼、通用交流偏好和通用协作约定；职业、长期目标、项目背景等普通长期信息进入 topics。引用、假设、角色扮演和单次要求不提取为用户核心事实。
- 提取前检查已有记忆，CORE 已覆盖则跳过；符合核心范围、仅 topics 已有的信息仍可加入 CORE，原主题保留。同主题增量补充，没有新增内容可以不写文件。冲突只提示未处理，本期不支持修改旧事实、遗忘、删除、精炼或容量治理。
- 后台结果在下一次交互或退出时分别展示核心与主题的写入情况；无新增不提示。失败提示说明受控原因，例如模型结束状态格式不合法或输出截断。正常退出等待队列完成。后台调用的用量和结束格式诊断单独记录在 `memory/extraction.jsonl`，不包含在前台费用统计中；该日志不保存对话、记忆或模型回复正文。失败任务不自动重跑。

例如输入“请记住：解释技术时先给最小示例”，主模型会调用 `remember` 写入 CORE；输入“我叫 Austin”无需额外要求记住，由后台调用 `write_core` 追加到 CORE，写入后后续模型请求会直接加载。其他可复用背景由后台筛选后写入主题。前台不因姓名尚未保存而追问是否记住，也不提前承诺后台已经保存。不要手工编辑程序生成的 MEMORY。正文文件开头含程序维护的 JSON 元数据注释，用于稳定 ID、来源与精确去重，不能随意删除该文件头。

代码调用可通过 `create_runtime(memory_dir=...)` 指定隔离记忆目录。测试还可使用 `memory_enabled=False` 或 `auto_memory=False`。注入主 `model` 或 `client` 时，后台默认不复用它们；要验证提取，显式传入返回独立模型的 `extraction_model_factory`。`wait_for_memory()` 等待后台，`drain_memory_events()` 读取完成状态。

首版后台队列运行在当前进程中，正常关闭会收尾；进程异常退出后的任务恢复和跨进程并发协调尚未实现。

## 图片输入

在 macOS 交互终端运行 `uv run kairos`，复制截图后按 **Ctrl+V**，或把图片文件拖入输入框。图片以 `[图片 N]` 标签显示，可以继续编辑问题，按 **Enter** 将文字和图片一起发送。只有图片时默认要求描述图片；**Alt+Enter** 可以换行。

- 图片标签右侧按 Backspace 移除附件，标签内的 Delete 也会移除整张图片。下方显示名称、加载状态及处理前后的尺寸。
- 可以连续添加多张图；加载在后台串行进行，期间可编辑文字。失败附件需要删除后重新添加，加载中不能提交。
- 支持完整图片路径的粘贴，包含引号或 shell 转义的空格、中文文件名。若终端拖放只插入普通路径，先在路径独占输入区时按 Enter 转成附件，再补充问题并发送。正文中提到的路径不会自动上传。
- Ctrl+V 主动读取系统剪贴板，支持截图位图、Finder 复制的图片文件和文字；普通文字粘贴不会顺带读取旧剪贴板图片。Cmd+V 是否能传图片由终端决定。
- `/help`、`/history`、`/think` 等命令不消耗待发图片；`/file 路径` 可把文本文件正文与待发图片一起提交。新建或恢复会话成功后清空附件草稿，旧会话历史继续保留。
- 请求失败且本轮输入被撤回时恢复原草稿；如果已保留完整模型回答或工具执行历史，则提示继续对话，不自动重新发送或执行工具。

第一版接受静态 **PNG、JPEG、WebP**，根据实际内容验证格式，校正 EXIF 方向，并按需缩放或压缩；动画、损坏或无法处理的图片会明确报错。项目限额为：输入文件 20 MiB、6400 万像素，处理后最长边 2000 像素、编码图片文件 3 MiB；整段会话最多 8 张、累计 Base64 16 MiB。数量和体积限制同时生效，超限只拒绝新增图片，不自动删除旧图。这些是项目策略，不等同于网关或厂商的通用上限。

图片加入草稿后保留处理好的内存快照，后续请求不再读取原文件；已发送图片随历史保存到 SQLite，退出并恢复会话后仍可用于追问和工具续轮。尚未发送的附件草稿不持久化。OpenAI 适配器转换为 `image_url` data URL，Anthropic 转为 `image.source`。暂不提供图片生成、独立看图模型或模型主动读图工具。

代码可使用 `load_image(path)` 和 `runtime.respond(prompt, images=(image,), on_event=handler)`；纯文字接口保持兼容。可选 `image_labels` 保留输入区中的稳定编号。真实载荷在 `runtime.messages` 中；`history()`、观察事件、JSONL 和错误展示使用图片摘要，不打印 Base64。图片用量采用 API 返回值。

## 命令

| 命令 | 作用 |
|---|---|
| `/new [标题]` | 新建并切换会话，保留旧会话；标题可省略 |
| `/sessions` | 查看已保存的会话和当前会话标记 |
| `/resume ID` | 恢复指定会话，支持唯一 ID 前缀 |
| `/rename 标题` | 重命名当前会话 |
| `/history` | 查看会话历史；图片仅显示摘要，实际请求保留完整图片 |
| `/history --ids` | 查看五类对象及 ID 关联，包含不再进入模型上下文的记录 |
| `/system 文本` | 使用新 system 提示词开启会话，保留旧会话；无参数时查看提示词 |
| `/think` | 切换已接入模型的思考模式并保存设置；未接入时明确提示 |
| `/file 路径` | 把一个文本文件的内容作为消息发出去 |
| `/reset` | 开启新会话，沿用 system 提示词和模型设置，保留旧会话 |
| `/exit` | 退出 |

模型协议通过 `~/.kairos/.env` 的 `KAIROS_PROVIDER` 选择：

```dotenv
KAIROS_PROVIDER=openai       # 当前示例是 DeepSeek 的 OpenAI 兼容接口
KAIROS_MODEL=deepseek-flash
KAIROS_API_KEY=...
```

`KAIROS_MODEL` 和 `GATEWAY_BASE_URL` 是必填配置，没有代码默认值；启动时缺少任一项会直接提示配置无效。

切换到 Anthropic Messages 时改成：

```dotenv
KAIROS_PROVIDER=anthropic
KAIROS_MODEL=deepseek-flash       # 网关支持 Anthropic 协议时保留网关模型别名
GATEWAY_BASE_URL=https://gateway.example/v1
# 可选：Anthropic SDK 的网关根地址；不填时自动去掉上面地址末尾的 /v1
ANTHROPIC_BASE_URL=https://gateway.example
```

当前 Anthropic 适配器使用 Python `anthropic` SDK；选择该协议前需要在运行环境安装它。SDK 的请求路径是 `/v1/messages`，因此 Anthropic SDK 使用的网关根地址不要重复包含 `/v1`。代码中的统一字段是 `Settings.gateway_base_url`，环境变量使用 `GATEWAY_BASE_URL`。

`KAIROS_API_KEY` 是通用的网关项目 Key；协议切换只改变请求格式和 Base URL，不需要更换 Key。

当前思考开关仅接入 OpenAI 兼容协议下名称以 `deepseek` 开头的模型。其他模型显示“思考切换未接入”，`/think` 不改写设置；这不表示上游模型没有推理能力。恢复以前错误保存为开启的未接入会话时，会纠正为关闭并提示。切换会话按目标模型判断支持情况，开启/关闭仅修改 `thinking` 参数，保留其他请求选项。

会话与待办数据共同保存在当前系统用户的 `~/.kairos/kairos.sqlite3`，会话使用独立的五张表；主程序从 `~/.kairos/.env` 读取模型和 API key 配置，环境变量仍可覆盖文件值。更换电脑后使用新电脑当前用户的主目录，不依赖项目位置或启动目录。配置和历史数据不会自动跨电脑同步。运行时的 `log_path` 可以由代码调用 `create_runtime()` 时显式传入。会话管理接口与返回值说明见 [会话系统设计的实现说明](docs/会话系统设计.md#第一版实现)。

待办支持新增、查询、修改、完成和删除，可直接输入“删除 ID 为 3 的待办”或“删除买牛奶这条待办”。删除工具按 ID 永久移除记录，未完成和已完成的待办均可删除；找不到 ID 时返回错误。助手收到标题描述时先查询定位，目标不明确时先询问。

待办函数在执行 SQL 前校验参数：ID 为严格正整数，优先级为整数 1～3，标签为非空字符串列表，截止时间为含时分秒与时区的 ISO 8601 时间（如 `2026-10-18T15:00:00+08:00`）。布尔值、错误字段类型、相对日期与无效日期会作为工具错误回传，不修改待办。`due_at`、`project` 可用 `null` 清空，标签可用空列表清空；已有历史数据不自动改写。
